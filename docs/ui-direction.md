# Benchmark console direction contract

**Planned — 2026-10-11 UTC:** The owner requested a bold, fun Svelte interface, model selection, and reporting, and asked for autonomous work while away. The assigned code-led direction was used without an approved visual comp. The concept seed key was `0ce90ca4`; it assigned direction 7. This is a provisional visual choice for the first build, not an owner-pinned brand rule.

## THESIS

Make every result traceable to a task and an exact run. The surface refuses a generic card leaderboard that hides small sample sizes.

## OWN-WORLD

A bright operator board: warm black controls, cream report paper, acid lime for active work, coral for misses, Bricolage Grotesque for short display type, DM Sans for controls, and JetBrains Mono only for measurements. The circular gauge is a crisp timing mark, not a progress claim.

## STORY

The owner chooses a source, served model, and prompt treatment, starts a bounded run, reads each task outcome, then opens exact run details. The first run is the pinned two-question smoke suite. Existing HA, coding, and Pi pilots appear in the activity trail.

## FIRST VIEWPORT

Desktop: narrow rail, large two-line measurement masthead, dark run controls at left, cream scorecard at right. The primary action follows the form rather than floating above it. At 390 px, the rail becomes a top strip, the gauge remains fully visible, and the two work panels stack.

## FORM

Assigned direction 7 from concept seed `0ce90ca4`: an operator board with legible, task-first reporting. The challenger review favored the board's product clarity. The code-led choice carries its ambition through an authored graphic mark, contrasting work surfaces, dense but explicit controls, and one readable result matrix. No approved comp was supplied.

## QUALITY BAR

The owner should identify the source, selected model, call limit, and paid guard before starting a run; no hosted call happens through a local fallback. Every outcome is pass, miss, unscored, or not run, never inferred from a missing score. The scorecard exposes exact run identity and settings on touch and keyboard. The mobile document has no page-level horizontal overflow. Results use actual Inspect logs and label the two-question limit.
